### 1. Welcome page for new signups and account claimers

Every newly created account now lands on a one-time welcome page (`/welcome`) before reaching the app — both fresh organiser signups and educators/students claiming an invited account.

- `src/app/welcome/page.tsx` (new): personalized greeting, chips for each olympiad the account joined, role-aware next steps (educator portal guidance, student results guidance, organiser application guidance), and a Get Started button leading to the original destination. ### 2. Per-school "Add Educator" button on the olympiad detail page

Previously educators could only be invited while *adding a new school* — the school picker matches schools by name, so schools already in an olympiad had no re-entry point and their educator lists were frozen. Organisers can now add educators to any school already participating.

- `src/app/organiser/olympiads/[olympiadId]/actions.ts` (new action): `addEducators(portalId, schoolId, formData)` is keyed by the school's row id (so it works for every participating school) and verifies the school belongs to the portal before writing. Failures return `{ error }` so the dialog stays open; the page is revalidated on success.
- `src/app/organiser/olympiads/[olympiadId]/AddEducatorButton.tsx` (new): accessible dialog (role=dialog, Escape/backdrop dismissal, body scroll lock) with the email-chip input pattern from the invite form.
- `src/lib/invites.ts` (new): the invite dedup/claim semantics — accepted member → skip, existing account → link directly, pending invite → re-send the original token, fresh address → insert `invited` + email — extracted into `inviteEducatorsToSchool()` and shared by both the original invite flow and the new action, so the two flows cannot drift.
- `src/app/organiser/olympiads/[olympiadId]/invite/actions.ts`: refactored onto the shared helper (~70 lines removed; DB call order preserved, so the existing FIFO-mock tests pass unchanged).
- `src/app/organiser/olympiads/[olympiadId]/page.tsx`: button wired into each participating school row, alongside the student head-count.
- Tests: `tests/app/add-educators.test.ts` (9), `tests/components/organiser/AddEducatorButton.test.tsx` (8).

### 3. Student results shown as raw mark plus percentage

Round results for students now show the mark out of the round's total alongside the percentage, in both places students see them.

- `src/app/(student)/results/[portalId]/rounds/[roundId]/review/page.tsx`: the Final Score box renders `18 / 25` with `72%` beneath. The total is the sum of the round's question marks — the same basis the auto-marker uses on submit. Rounds with no questions in the bank (manually graded paper rounds) fall back to the raw mark alone.
- `src/app/(student)/results/[portalId]/RoundTabs.tsx`: the "Your Final Result" card shows the raw mark, the total, and the percentage.
- `src/app/(student)/results/[portalId]/page.tsx`: one aggregate query (`sum(questions.marks)` grouped by round) feeds each round's `maxScore` into RoundTabs.
- Tests: `tests/app/review-page.test.tsx` (4), `tests/components/student/RoundTabs.test.tsx` (4).
